## 1. 定位与红线

做一款开源的跨平台规则型代理客户端：按规则把流量分发到不同出站协议，核心与界面分离，先交付能日常使用的最小闭环。

红线（为开源发布与避免权属纠纷而定，全员遵守）：

1. **命名卫生**：产品名、仓库、代码、注释、文档、提交信息中，不出现任何非开源商业产品的名称、商标、图标、文案。协议名称（见 §2）是公开协议规范的名词，不在此限。
2. **干净室实现**：全部代码原创。功能设计可以参考公开协议规范与公开文档，不复制任何专有实现的代码与资产。
3. **许可证一致**：本项目 GPLv3；引入的第三方组件必须是 GPLv3 兼容的开源许可证，逐项登记在 §7。

## 2. MVP 功能范围

### 2.1 平台与形态
- Windows、Linux 桌面端（x86_64）
- 核心守护进程 + 桌面 UI + 基础 CLI，三者分离（见 §3）

### 2.2 入站
- HTTP / SOCKS5 代理服务（本地监听，可选认证）
- 系统代理设置（跟随核心启停）
- TUN 模式接管全局流量（Windows: Wintun；Linux: tun 设备 + 路由配置）

### 2.3 出站协议
- Shadowsocks（含 2022 系列密码套件）
- VMess（AEAD）
- VLESS（含 REALITY、XTLS-Vision flow）
- Trojan
- Snell v4 / v5
- Hysteria2
- TUIC v5
- SOCKS5（含 TLS 变体）
- HTTP / HTTPS

### 2.4 规则引擎
- 规则类型：DOMAIN、DOMAIN-SUFFIX、DOMAIN-KEYWORD、DOMAIN-SET、IP-CIDR、IP-CIDR6、GEOIP、IP-ASN、RULE-SET、DEST-PORT、PROTOCOL、FINAL
- 外部规则集（RULE-SET / DOMAIN-SET）定时更新、本地索引、循环引用检测
- 保存前整体校验：规则集引用存在性、策略引用存在性、FINAL 收尾；校验不过不生效
- 规则匹配解释：给定域名/IP 输出命中规则与决策路径（CLI 先行）

### 2.5 策略组
- Select（手动选择）
- URL-Test（定时测速、自动选最快）
- Fallback（按序故障转移）

### 2.6 配置与导入
- 原生配置：INI 风格分节纯文本（[General] / [Proxy] / [Proxy Group] / [Rule] / [Host]），可手改、可版本管理
- 分享链接导入：vmess://、vless://、ss://、trojan://、hysteria2://、tuic:// 等
- 订阅链接导入与定时更新
- GeoIP / ASN 数据库：兼容 mmdb 格式

### 2.7 界面与观测
- 主界面：配置切换、出站与策略组列表及切换、实时连接列表、上下行流量曲线、日志查看
- 系统托盘：启停、模式切换、节点切换
- 液态玻璃质感（半透明 + 背景模糊）与弹簧曲线动效，素材全部原创
- 连接日志与流量统计本地持久化（SQLite）

## 3. 架构

```
+----------------------------------------------------------+
|  客户端：桌面 UI（Tauri） | CLI                          |
+---------------------------+------------------------------+
                            | 本地 API（HTTP/JSON，仅回环，
                            | 随机令牌鉴权；Windows 可用
                            | named pipe，Linux 用 socket）
+---------------------------v------------------------------+
|  核心守护进程（常驻）                                    |
|  +-- 配置层：解析、订阅更新、校验、热重载                |
|  +-- 规则引擎：编译为索引结构，匹配 + 解释               |
|  +-- 策略层：出站抽象 + 策略组                           |
|  +-- 协议层：每协议一个出站实现                          |
|  +-- DNS 层：系统 DNS / 明文上游、缓存、[Host] 本地映射   |
|  +-- 入站层：HTTP/SOCKS5 入站、TUN 入站                  |
|  +-- 观测层：连接表、流量统计、日志（SQLite）            |
+----------------------------------------------------------+
```

要点：
- UI 退出或崩溃不影响代理运行；CLI 与 UI 平权，共用同一本地 API。
- 特权操作（TUN、路由、系统代理）收敛在核心进程内处理，UI 不提权。

## 4. 技术选型

| 层 | 选型 | 说明 |
|---|---|---|
| 核心语言 | Go | 三平台单代码库交叉编译；并发模型适合大量连接；单个静态二进制分发 |
| TUN | Windows: Wintun；Linux: tun + netlink；用户态协议栈在技术验证期定（gVisor netstack 或同类开源栈） | MVP 以稳定接管流量为准 |
| QUIC 家族（Hysteria2 / TUIC） | quic-go | Go 生态成熟的开源 QUIC 实现 |
| WireGuard | 第一版不含（不在 MVP 协议清单） | — |
| UI | Tauri 2 + Web 前端（框架在脚手架期定） | 体积小；液态玻璃用 CSS 背景模糊与半透明层实现 |
| 持久化 | SQLite | 流量统计、测速历史、日志 |
| 构建与发布 | GitHub Actions 构建 Win/Linux 安装包 | 源码与构建脚本一并开源 |

## 5. 性能目标（绝对指标，发布前实测留档）

| 指标 | 目标 |
|---|---|
| 单连接吞吐（直连与主流协议） | 跑满千兆线路 |
| 规则匹配 | 10 万条规则规模下单次匹配 < 1ms（索引化匹配，不做线性扫描） |
| 连接建立附加延迟 | 相比直连的额外开销 p50 < 5ms（同机回环出站除外情形需注明） |
| 核心进程内存 | 空闲 ≤ 80MB；1000 并发连接 ≤ 300MB |

达不到的指标要在发布说明中如实写明差距，不写"性能强劲"之类无数据表述。

## 6. MVP 验收标准

1. Win 与 Linux 两平台均可安装、启动、常驻托盘。
2. 导入一份含 §2.3 全部协议节点的订阅后，每个协议至少一个节点实测连通。
3. 系统代理与 TUN 两种模式均可接管浏览器流量并按规则分流（直连/代理/拦截三类规则各验一条）。
4. 策略组三种类型行为正确：Select 手动切换即时生效；URL-Test 能自动切到最快节点；Fallback 在首选节点断开后自动转移。
5. §5 性能指标全部实测并留档。
6. 仓库公开前完成一次命名卫生检查：全仓文本检索确认无非开源商业产品名称与资产。
